## What to add to `tests/integration/docker-compose.yml`

```yaml
ollama:
  image: ollama/ollama:latest
  ports: ["11434:11434"]
  volumes: [ollama_models:/root/.ollama]
  command: serve
  healthcheck:
    test: ["CMD", "curl", "-fsS", "http://localhost:11434/api/tags"]
    interval: 5s
    timeout: 5s
    retries: 30
ollama-init:
  image: ollama/ollama:latest
  depends_on:
    ollama:
      condition: service_healthy
  entrypoint: ["sh", "-c"]
  command: |
    ollama pull llama3.1:8b &&
    ollama pull mxbai-embed-large

volumes:
  ollama_models:
```

## Traps

- **Cold-start latency** — `ollama-init` may take 5-10 minutes to pull both models on first run. Volume cache makes subsequent runs fast. Set `pytest --timeout=600` for the suite.
- **Streaming-bug workaround** — the M4 upstream bug (T124 Issue 1) may bite some tests. Pin the chat model to `llama3.1:8b` everywhere; if `qwen2.5` triggers the bug, document it.
- **The streaming test must check token count, not full response** — Ollama's responses are non-deterministic. Don't assert response text equality; assert token count > N and that `tools_called` is non-empty.
- **Concurrent test isolation** — pytest's default test isolation may not be enough. Use `pytest-asyncio` or explicit ThreadPoolExecutor; don't rely on test ordering.
- **GCE prod analog** — these tests run against a docker container; production runs against `localhost:11434` on a customer DGX. The contract is the same Ollama HTTP API, so test coverage transfers.

## Red team round 1 revisions (H8, H12, M18, L7)

### H8 — Declare `ollama_only_env` fixture in `tests/conftest.py` for cross-tier reuse

The Ollama-only integration tests will silently fall back to OpenAI because `conftest.py` auto-loads `.env`. Without `monkeypatch.delenv`, half the tests pass for the wrong reason.

**Required:** declare the fixture in `tests/conftest.py` so all tiers reuse it:

```python
# tests/conftest.py
@pytest.fixture
def ollama_only_env(monkeypatch):
    """Force tests to use Ollama by removing OpenAI env vars.

    conftest.py auto-loads .env which usually contains OPENAI_API_KEY.
    Without this fixture, an Ollama test silently falls back to OpenAI
    and reports green for the wrong reason.
    """
    monkeypatch.delenv("OPENAI_API_KEY", raising=False)
    monkeypatch.delenv("OPENAI_BASE_URL", raising=False)
    yield
```

Then every Ollama-only integration test uses it explicitly:

```python
def test_advisory_query_via_ollama_byok_full_chain(test_client, ollama_only_env):
    ...
```

The "concurrent Ollama + OpenAI" test (`test_concurrent_advisory_no_cross_contamination`) intentionally keeps OPENAI_API_KEY and does NOT use the fixture.

### H12 — Negative read-back for rejected save tests

The original Tier-2 save test inventory lists rejection cases (`rejects_missing_model_for_ollama`, `rejects_phi3_for_ollama`) without a follow-up GET to confirm the DB was not silently mutated. DataFlow could partial-write on the rejected path.

**Required:** every reject test must follow the failing POST with a GET:

```python
def test_save_config_rejects_phi3_for_ollama_no_db_write(test_client, db, ollama_only_env):
    pre = test_client.get("/api/llm-config").json()
    resp = test_client.post("/api/llm-config", json={"provider": "ollama", "model_pref": "phi3:14b", "base_url": "http://ollama:11434"})
    assert resp.status_code == 400
    post = test_client.get("/api/llm-config").json()
    assert pre == post, "DB was mutated despite the rejection"
```

### M18 — Replace full-app subprocess test with minimal Python invocation

The original `test_app_refuses_to_start_with_phi3_ollama_model` spawns the full uvicorn + DataFlow + Nexus stack just to test a 5-line invariant function. Slow, flaky, dependent on unrelated services. Replace with:

```python
def test_init_invariant_subprocess_phi3_rejected():
    import subprocess
    result = subprocess.run(
        [
            sys.executable,
            "-c",
            "from hr_advisory.api.server import _validate_env_invariants; _validate_env_invariants()"
        ],
        env={**os.environ, "OLLAMA_BASE_URL": "http://x:11434", "OLLAMA_MODEL": "phi3:14b", "OPENAI_API_KEY": ""},
        capture_output=True,
        text=True,
    )
    assert result.returncode != 0
    assert "phi3" in result.stderr or "tool-capable" in result.stderr
```
